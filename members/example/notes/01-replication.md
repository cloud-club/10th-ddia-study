# 예시: 복제 지연과 읽기 일관성

> 작성·집계 흐름을 확인하기 위한 테스트 노트입니다. `example`은 실제 참여자가 아닌 테스트용 작성자이며, 일반 노트와 동일하게 집계됩니다.

## 이번에 답하려는 질문

- 주 복제본에 쓴 직후 다른 복제본에서 읽으면 왜 이전 값이 보일 수 있을까?
- “내가 쓴 값을 읽는다”는 보장은 모든 사용자가 같은 최신 값을 본다는 뜻일까?

## 한 줄 요약

비동기 복제에서는 쓰기가 주 복제본에 반영된 뒤에도 다른 복제본이 따라잡기 전까지 오래된 값을 반환할 수 있다.

## 핵심 내용

### 복제 지연이 만드는 읽기 문제

클라이언트가 주 복제본에 `name = "Mina"`를 기록하고 곧바로 읽기 복제본에 조회를 보낸다고 해 보자. 복제본이 아직 변경 내용을 적용하지 않았다면 예전 이름을 돌려줄 수 있다. 쓰기 요청의 성공과 모든 복제본의 최신 상태는 같은 의미가 아니다.

```text
클라이언트 ──쓰기──▶ 주 복제본 ──비동기 복제──▶ 읽기 복제본
     └──────────────── 조회 ────────────────────▶
                                 아직 적용 전이면 이전 값
```

### 보장은 서로 다르다

| 보장 | 사용자가 기대하는 것 | 보장하지 않는 것 |
|---|---|---|
| 읽기-자기-쓰기(read-your-writes) | 내가 방금 쓴 값은 이후 내 읽기에서 확인할 수 있음 | 다른 사용자도 그 값을 즉시 본다는 것 |
| 단조 읽기(monotonic reads) | 한 번 본 값보다 과거 상태로 되돌아가지 않음 | 모든 읽기가 전역적으로 최신이라는 것 |
| 일관된 접두사(consistent prefix) | 인과 순서가 있는 쓰기를 같은 순서로 관찰함 | 서로 인과관계가 없는 쓰기의 단일 전역 순서 |

따라서 “복제본이 있다”만으로 읽기 일관성을 단정하지 않는다. 어떤 복제본에서 읽는지, 복제 지연을 어떻게 다루는지, 사용자에게 어떤 보장을 약속하는지를 함께 정해야 한다.
