01 /

책 한 권을, 세 장면으로.

기초를 이해하고 → 여러 서버의 문제를 다루고 → 데이터 흐름 전체를 연결합니다. 같은 주문 서비스를 세 가지 관점으로 바라보면 파트의 차이가 보여요.

PART01

먼저, 잘 담고 잘 꺼내기

주문 서비스를 만든다고 해볼게요. 주문을 저장할 수 있게 됐다고 설계가 끝난 것은 아니에요. 고장에도 주문이 남아야 하고, 사용자가 늘어도 감당해야 하며, 새 기능도 추가할 수 있어야 합니다. Part 1은 이 기준을 세운 뒤 정보의 모양 → 저장·조회 방법 → 형식의 변화로 질문을 이어갑니다.

  • 잘 동작한다는 것은 무엇일까? · 1장고장에도 주문을 지키고, 부하가 늘어도 대응하고, 나중에 바꾸기 쉬워야 합니다. 이후 기술을 비교할 기준부터 세워요.
  • 주문과 고객을 어떤 모양으로 담을까? · 2장함께 읽을 정보는 묶고 싶지만, 여러 곳에 복사하면 변경이 어려워져요. 표·문서·그래프를 어떤 질문에 쓸지 비교합니다.
  • 담은 데이터를 빨리 찾으려면? · 3장파일에 쓰는 것만으로는 조회가 빨라지지 않아요. Index와 저장 구조가 읽기·쓰기·공간 비용을 바꾸는 이유를 봅니다.
  • 새 기능을 넣어도 옛 앱은 읽을 수 있을까? · 4장데이터와 코드가 서로 다른 시점에 바뀔 수 있어요. 새 버전과 옛 버전이 함께 동작할 형식과 약속을 다룹니다.

주문 서비스로 보면주문·고객 정보를 어떻게 묶고 찾을지, 배송 메모 필드를 추가해도 옛 앱이 읽을 수 있을지 고민하는 단계예요.

PART02

여러 대가 되면, 무엇이 어려울까?

한 서버에 데이터가 있으면 그 서버의 장애나 용량 한계가 문제가 됩니다. 복사하거나 나눠 맡기면 도움이 되지만, 이제 서로 다른 값·동시 변경·통신 지연을 다뤄야 해요. Part 2는 여러 서버를 쓰는 이유 → 그 때문에 드러나는 문제 → 지킬 수 있는 약속으로 이어집니다. 동시 실행 문제는 한 DB에서도 생길 수 있어요.

  • 같은 데이터를 다른 서버에도 두면? · 5장고장에 대비하고 읽기를 나눌 수 있어요. 대신 변경이 늦게 전달되거나 여러 곳의 쓰기가 충돌할 수 있습니다.
  • 전체 데이터가 한 대에 안 들어가면? · 6장서로 다른 데이터를 나눠 맡겨요. 어디로 나누고, 일이 몰리면 어떻게 옮기며, 담당 서버를 어떻게 찾을지 봅니다.
  • 작업이 중간에 실패하거나 요청이 겹치면? · 7장이체의 절반만 성공하거나 두 예약이 겹치지 않게 하려면 어떤 Transaction 보장이 필요한지 살펴봅니다.
  • 다른 서버가 제때 답하지 않는다면? · 8–9장응답·시각·실행 속도를 믿기 어려운 상황을 먼저 본 뒤, 그래도 같은 값과 결정을 따르게 할 절차와 비용을 알아봐요.

주문 서비스로 보면저장했는데 옛 주문이 보이거나, 마지막 한 자리를 두 사람이 예약하거나, 응답이 없어 주문 성공 여부를 모르는 상황을 다뤄요.

PART03

데이터를 가공하고 시스템을 연결하기

주문 한 건을 저장하고 읽는 일을 넘어, 쌓인 주문으로 판매량과 검색 화면을 만들고 싶어집니다. Part 3은 모인 데이터 계산하기 → 새 변경을 계속 반영하기 → 여러 결과를 하나의 흐름으로 맞추기로 이어져요. 마지막에는 그 결과를 사람에게 적용할 때의 책임으로 질문을 넓힙니다.

  • 쌓인 기록에서 결과를 만들려면? · 10장작은 로그 분석에서 시작해 여러 컴퓨터로 계산을 나누고 다른 자료를 연결합니다. 복잡한 계산과 다시 실행하는 방법으로 이어져요.
  • 새 주문도 지금 반영하려면? · 11장작업이 끝날 때까지 기다리지 않고 결과를 계속 갱신해요. 늦게 온 주문과 중복, 장애 뒤 복구 문제가 따라옵니다.
  • 검색·통계·DB가 서로 다른 상태라면? · 12장원본의 변경을 다른 결과들이 어떻게 따라올지 전체 흐름을 봅니다. 끝에서는 정확한 처리뿐 아니라 데이터 사용이 사람에게 미치는 영향도 묻습니다.

주문 서비스로 보면주문 기록으로 어제의 판매량을 만들고, 새 주문을 인기 상품 화면에 반영하며, 검색 Index와 캐시까지 연결하는 단계예요.

이 가이드의 기준과 책에서 찾아볼 곳

마틴 클레프만의 『데이터 중심 애플리케이션 설계』 첨부 한국어 PDF를 바탕으로 만든 비공식 학습 가이드입니다. 목차의 3부·12장 구성과 각 장의 핵심 본문을 확인해, 문제·작동 원리·선택의 대가를 설명하고 도해로 재구성했습니다. 책 전체를 대체하는 요약이나 최신 제품 기능 안내가 아닙니다.

상황 예시, 그림, 확인 질문은 학습용으로 새로 구성했습니다. 알고리즘 구현·성능 벤치마크가 아니며, 12장의 미래 방향은 저자의 제안이지 유일한 정답이 아닙니다.

아래 쪽수는 책에 인쇄된 쪽수입니다. 이 첨부 파일에서 PDF 뷰어의 페이지 번호는 인쇄 쪽수보다 26 큽니다. 원본 PDF는 이 사이트에 포함하거나 업로드하지 않았습니다.

읽음 표시는 이 브라우저의 로컬 저장소에만 보관합니다. 서버 전송·계정·추적 도구·외부 글꼴 요청은 없습니다. 저장소가 차단된 환경에서는 현재 화면을 사용하는 동안만 표시가 유지됩니다.
