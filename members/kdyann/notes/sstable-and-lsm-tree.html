SSTable과 LSM 트리 비교

1. Intro

3장을 읽으면서 SSTable과 LSM 트리의 차이가 헷갈렸다. 둘 다 정렬된 데이터를 저장하고, 파일을 병합하며, 컴팩션으로 오래된 값을 정리한다는 설명이 나오는데...

구분하려면 각각이 가리키는 범위를 보면 된다. SSTable은 정렬된 파일이고, LSM 트리는 메모리와 정렬된 파일들을 함께 관리하는 구조다. 이 관점에서 쓰기와 조회 과정을 다시 따라가 봤다.

2. SSTable

2.1. 정의

  • Sorted String Table. 키 순서로 정렬된 키·값 레코드를 담는 파일이다.
  • LevelDB·RocksDB 같은 엔진에서 디스크에 데이터를 저장하는 단위로 사용한다.

2.2. 특징

  • 키가 정렬돼 있다.
    • 모든 키의 위치를 메모리에 보관하지 않아도, 일부 키의 위치를 담은 희소 색인으로 탐색 범위를 좁힐 수 있다.
    • 정렬된 파일끼리는 순서대로 읽으며 병합하기 쉽다.
  • 완성된 파일은 제자리에서 수정하지 않는다.
    • 값을 바꿀 때는 새 버전을 다른 곳에 기록한다. 같은 키의 여러 버전이 서로 다른 파일에 남을 수 있다.
  • 파일을 병합하는 주체는 저장소 엔진이다.
    • SSTable은 병합 작업의 입력이나 결과가 되는 파일이다.

3. LSM 트리

LSM 트리(Log-Structured Merge-Tree)는 쓰기를 메모리에 모았다가 정렬된 파일로 내리고, 여러 파일을 병합하며 관리하는 구조다. 대표적인 현대 구현에서는 이 디스크 파일로 SSTable을 활용한다.

SSTable은 “어떤 파일인가”를 설명하고, LSM 트리는 “새 쓰기와 여러 파일을 어떻게 관리하는가”를 설명한다.

3.1. 구성 요소

  • 멤테이블(memtable): 아직 파일로 내리지 않은 쓰기를 메모리에 모아 둔다. RocksDB의 기본 구현은 스킵 리스트이며, 항상 B 트리인 것은 아니다.
  • WAL(write-ahead log): 메모리의 쓰기를 장애 후 복구하기 위한 로그다. 저장 장치에 동기화하는 시점에 따라 내구성 보장이 달라진다.
  • SSTable: 멤테이블의 내용을 정렬된 상태로 디스크에 저장한다. 실제 엔진에는 여러 파일과 레벨이 존재할 수 있다.

3.2. 쓰기

  1. 멤테이블에 새 값을 기록한다. 예를 들어 B=1, A=2를 쓰면 키 순서로는 A=2, B=1이 된다. 복구를 위해 WAL에도 변경을 남긴다.
  2. 멤테이블이 일정 크기에 이르면 파일로 내린다. 정렬된 내용을 SSTable로 만드는 과정을 플러시(flush)라고 한다.
  3. 이후 쓰기는 새 멤테이블이 받는다. 이미 완성된 SSTable은 그대로 두고, 수정된 값도 새 기록으로 추가한다.

3.3. 조회

  1. 멤테이블에서 먼저 확인한다. 아직 파일로 내리지 않은 최신 쓰기가 있을 수 있다.
  2. 필요한 SSTable을 확인한다. 단순한 모델에서는 최신 파일부터 찾는다. 실제 엔진은 레벨·키 범위·블룸 필터 등으로 후보 파일을 줄인다.
  3. 최신 기록으로 결과를 결정한다. B의 새 값이 3이면 이전 값 1을 반환하지 않는다. A의 최신 기록이 삭제 표시라면 값이 없다고 답한다.

3.4. 병합과 컴팩션

  • 정렬된 파일들을 병합한다. 각 파일이 정렬돼 있어도 파일 사이에는 같은 키의 여러 버전이 남을 수 있다.
  • 필요 없어진 이전 버전을 정리한다. 예를 들어 B=1과 B=3이 남아 있다면 최신 값인 3을 유지할 수 있다.
  • 새 파일을 안전하게 반영한 뒤 이전 파일을 정리한다. 데이터를 다시 쓰는 작업이므로 디스크 I/O와 쓰기 증폭이 발생한다.

삭제는 툼스톤(tombstone)이라는 특수 기록으로 표현한다. 다른 파일에 옛 값이 남아 있는데 삭제 표시만 먼저 지우면 그 값이 다시 나타날 수 있다. 따라서 삭제 표시와 이전 버전을 버려도 안전한지 확인해야 하며, 과거 버전을 필요로 하는 스냅숏도 고려해야 한다.

아래 예시에서 B=1, A=2를 쓴 뒤 B=3으로 수정하고 A를 삭제해 보자. 각 단계에서 메모리와 파일이 어떻게 달라지는지 확인할 수 있다.

처음 B=1, A=2를 멤테이블에 쓴 뒤 플러시하면 SSTable 1에는 A=2, B=1이 저장된다. 이후 B=3과 A의 삭제 표시를 새 멤테이블에 쓰고 다시 플러시하면 SSTable 2가 생긴다. B 조회는 최신 파일에서 3을 반환하고, A 조회는 최신 파일의 삭제 표시를 보고 없음으로 처리한다.

두 파일을 모두 컴팩션하면 새 SSTable 3에 B=3만 남길 수 있다. 이 예시는 A의 옛 버전이 모두 병합 대상에 포함돼 있고, 이전 버전을 필요로 하는 스냅숏도 없는 경우다.

4. 정리

  • SSTable은 키 순서로 정렬된 파일이고, LSM 기반 엔진의 디스크 저장 단위가 된다.
  • LSM 트리는 메모리와 여러 정렬 파일을 관리하는 구조이며, 쓰기·플러시·조회·컴팩션을 함께 봐야 이해할 수 있다.
  • 새 쓰기를 모아서 처리하는 대신 나중에 병합하는 비용이 따른다. 컴팩션이 밀리면 읽기와 쓰기가 느려질 수 있으므로 모든 작업에서 B 트리보다 빠르다는 뜻은 아니다.
